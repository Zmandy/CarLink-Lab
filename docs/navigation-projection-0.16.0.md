# 导航投屏实验版 0.16.0

本版在已经运行的 CarLife 连接上切换视频来源，支持胎压仪表与 Android 屏幕共享。ELM327 采集不随画面切换停止。

## 使用

1. 覆盖安装 0.16.0；保留原有应用数据和连接参数。
2. 打开“连接车辆与实时仪表”，开始连接，确认车机出现原有仪表。
3. 在车辆连接页找到“导航投屏 · 实验功能”，点击“开始导航投屏”。车机视频未就绪时按钮不可用。
4. 在系统授权界面选择导航应用或整个屏幕并确认。单应用共享是否可用取决于系统版本与厂商实现。共享整个屏幕时，车机会显示屏幕上的其他内容。
5. 在手机打开导航并设置路线。建议让导航使用横屏，保持手机亮屏。画面按车机协商尺寸编码；系统可能按比例缩放并保留黑边。
6. 返回本应用点击“恢复胎压仪表”，或使用后台连接通知中的同名按钮，结束共享并切回仪表。
7. 重新投屏需要重新授权。系统终止共享时，若车机仍在请求视频，自动恢复仪表；如果车机停止视频或断开，则等待车机重新请求视频后显示仪表。

本版导航仍在手机操作，投屏不传导航音频。现有手机/蓝牙音频路径可另行使用；不保证锁屏投屏持续运行。

## 画面链路

```text
Android 系统屏幕共享 → VirtualDisplay → MediaCodec Surface → H.264
                                                        ↓
胎压仪表 → 原有 H.264 编码器 ──────────────→ CarLife 视频通道 → 车机
```

两个来源互斥。每次切换使旧来源的发送回调失效，避免旧画面继续混入。屏幕共享会话只创建一次 VirtualDisplay；恢复仪表后释放共享显示、编码器和授权会话。进程重启只恢复车辆连接，不自动重新采集屏幕。

## 实车验证

在停车状态下按顺序检查并记录结果：

| 项目 | 预期 |
| --- | --- |
| 未连接车机 | 开始导航投屏按钮不可用 |
| 取消授权 | 仪表继续显示 |
| 导航应用或全屏共享 | 车机出现导航，地图变化持续更新 |
| 手机旋转/导航缩放 | 画面持续更新；记录黑边、比例和文字可读性 |
| 导航运行 10 分钟 | 记录延迟、发热、断流情况 |
| 恢复仪表 | 车机重新显示最新车辆数据，屏幕共享结束 |
| 再次开始投屏 | 再次出现系统授权界面，可成功投屏 |
| 系统停止屏幕共享 | 自动恢复仪表 |
| 投屏期间停止车辆连接 | 结束屏幕共享和车辆连接 |
| 拔插 USB 后重连 | 显示仪表；投屏需重新授权 |
| 锁屏后解锁 | 记录厂商系统是否终止共享；终止后应恢复仪表 |

连接页可展开并复制日志，重点观察 `VIDEO NEGOTIATED`、`导航画面采集已启动`、`导航首帧已编码并提交 CarLife 视频通道` 和共享停止原因。首帧日志只表示已编码并提交发送，不证明车机已经成功解码。

## 构建与验证范围

Windows JDK 17、Android SDK 35，在项目目录执行：

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

本版签名与已交付的 0.15.0 APK 核对。迁移配置原先引用的 `linux-debug.keystore` 与该 APK 的证书不同，本次改为单独的 `carlife-debug.keystore`，从现有匹配签名复制，未覆盖任何原有密钥文件。自动测试覆盖 H.264 Annex B 数据保留、长度前缀转换、参数集拼接及无效长度拒绝。构建与静态检查不能替代 MediaProjection 授权、手机硬件编码及车机解码的实机验证。
