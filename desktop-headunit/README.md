# CarLink 电脑模拟车机 0.1.0

这是配套 CarLink Lab 0.16.1 的 Windows CarLife 接收端。可以在电脑上完成协议握手、视频参数协商、H.264 接收解码、暂停/继续、断开重连、截图和原始视频记录。

## 不用安装，解压即用

需要 Windows 10/11 x64，自带 .NET Framework 4.x。完整解压后双击 `START.cmd` 或 `CarLinkHeadUnit.exe`。ADB 和 FFmpeg 已随包提供，不需要 Python、Java 或 Android Studio。

### 没有手机，先测试接收器

点击“本地自检”，窗口应显示动态测试图。可以切换分辨率（先断开）、暂停、继续和截图。测试图由电脑生成，经过模拟手机的 CarLife 消息封装，再由接收器解析、解码；这只验证接收器链路，不代表 Android APP 的导航已经通过测试。

双击 `SelfTest.cmd` 可以自动检查：10 项协议边界检查（包括固定报文、分片、截断、长度限制与整数溢出）、ADB 设备列表解析，以及 800×480 / 1024×600 的握手、解码、暂停和继续。视频集成检查结果保存到 `self-test.txt`。

### 接收手机 APP 的真实画面

1. 手机安装此前的 CarLink Lab 0.16.1，开启 USB 调试或无线调试，并授权这台电脑。
2. 新笔记本可双击 `PairPhone.cmd` 进行无线配对、连接。配对地址和连接地址的端口通常不同；旧配对码不能复用。
3. 在手机 APP 的“车辆连接”页面点击“开始连接”。不需要真实车机；没有 ELM327 时仪表显示等待数据，不影响视频链路验证。
4. 桌面点击“刷新设备”，选择对应手机，再点击“连接 APP”。默认 800×480、15 fps。
5. 窗口应显示 APP 实际编码发送的仪表；“解码帧”和“视频包”计数应增长。
6. 手机点击“开始导航投屏”并完成系统授权，再打开导航。电脑应显示手机实际发送的共享画面。建议手机横屏，保持亮屏。
7. 点击“暂停视频”会请求 APP 停止视频；如果正在屏幕共享，该共享会话也会被结束。“继续视频”默认恢复仪表，再次投屏需重新授权。
8. 完成测试后点击“断开连接”。工具会关闭自己建立的 TCP 通道，并只移除本会话分配的 ADB 转发。

电脑接收器与真实车机不要同时连接同一个 APP 实例。切换分辨率或帧率之前先断开，再重新连接。

### 在电脑上运行 Android APP

此工具也接受通过 ADB 连接的 Android 模拟器（例如设备名 `emulator-5554`）。在模拟器中安装同一个 APP、开始连接，然后在本工具里选择模拟器，即可进行 PC 上的 APP 与车机接收端联调。

本工具包不包含 Android 模拟器或系统镜像。Android 模拟器需要单独配置；“本地自检”不是 Android 模拟器。模拟器验证后仍需在真实手机和车机验证 USB、厂商后台策略和硬件解码兼容性。

## 窗口和文件

- 分辨率：800×480、1024×600、1280×720；帧率：10/15/20/30。
- 解码帧：实际输出的画面数；视频包：接收到的 CarLife 视频消息数量，两者不一定相等。
- fps：最近采样区间内的解码速率；Mbps：本次会话平均输入视频码率，不是端到端延迟。
- “保存截图”保存收到的原始画面，保持协商分辨率；显示区域按比例缩放，黑边可能来自手机投屏本身。
- 默认勾选“保存 H.264”，会话目录包含 `session.log`、`video.h264` 和截图。目录在 `logs` 下，可点击“打开日志目录”。
- 手机仪表刚开始编码时可能先出现几帧黑色，随后 WebView 内容才加载完成。
- 解码器提示 `not enough frames to estimate rate` 是低探测缓存启动时的提示；如果帧计数持续增加且图像正常，并不表示连接失败。

本版不实现触摸反控、音频播放、ELM327/ECU 仿真、车机系统固件或真实 USB CarLife 主机。现阶段用于验证现有 APP 的上层协议与视频链路。

## 协议与源码

项目源码在原 Android 项目的 `desktop-headunit` 目录；独立交付包在 `source` 下附带相同源码。先关闭运行中的接收器，再使用 Windows 自带 C# 编译器构建：

```powershell
.\source\build.ps1 -Destination .
```

调试程序会通过 ADB 给手机的 7240/8240/9240/9241/9242/9340 通道建立动态本地转发，仅使用控制和视频数据，其他通道建立连接占位。消息头与当前 `CarLifeClient.java` 一致：控制消息 8 字节头，视频消息 12 字节头，均按大端读取。

自动集成检查：

```powershell
$p = Start-Process .\CarLinkHeadUnit.exe -ArgumentList '--self-test' -PassThru -Wait
$p.ExitCode
```

`--phone-test 设备序列号` 可自动验证真实手机的握手、解码、暂停/继续和两轮重连；执行前必须在 APP 开始连接，且不能有另一个接收器占用该 APP。测试退出码非零时查看 `startup-error.txt`。该检查会改变 APP 的视频开始/暂停状态。

## 依赖来源

FFmpeg 使用独立进程解码，来源为 FFmpeg 官方下载页所列的 Gyan Windows 构建，下载时核对发布方 SHA-256。许可与来源记录见 `licenses/ffmpeg`。ADB 的许可见 `tools/NOTICE.txt`。本项目不把 FFmpeg 库链接进桌面程序。
